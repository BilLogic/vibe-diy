# User Research Guide

## Jobs-to-Be-Done (JTBD) Framework

For any design task, identify:
1. **What job is the user hiring this product to do?**
2. **What's the current alternative?** (how do they solve it today)
3. **What would make them switch?** (the pull toward the new solution)
4. **What holds them back?** (anxiety, switching cost, habits)

## Workshop Example (Worked)

**User:** CMU design student considering the Compound Designing workshop

| JTBD Element | Answer |
|-------------|--------|
| Job | Decide if this workshop will teach me something valuable for my career |
| Current alternative | YouTube tutorials, self-directed experimentation with AI tools |
| Pull | Structured approach, hands-on practice, expert guidance, credential (CMU event) |
| Pushback | Time cost (60 min), unclear prerequisites, might be too basic/advanced |

## Persona Synthesis Template

When creating or refining a user persona:

```
Name: [representative name]
Role: [student/professional/etc.]
Goal: [primary job-to-be-done]
Context: [when/where they encounter this]
Pain points: [what frustrates them about current alternatives]
Success criteria: [how they'll judge if this was worthwhile]
```

## Journey Mapping Checklist

For each stage of the user journey:
- [ ] What is the user's goal at this stage?
- [ ] What information do they need?
- [ ] What emotions are they likely feeling?
- [ ] What could go wrong?
- [ ] What SDS components best serve this stage?
- [ ] How do we measure success at this stage?

## Research Methods (for context)

| Method | When to use | Output |
|--------|-------------|--------|
| JTBD interviews | Understanding motivation | Job statements |
| Journey mapping | Visualizing the experience | Stage-by-stage map |
| Competitive analysis | Positioning decisions | Comparison matrix |
| Heuristic evaluation | Assessing existing designs | Issue list with severity |
